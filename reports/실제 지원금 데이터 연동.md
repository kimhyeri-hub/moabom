# 확인된 열두 정책을 예시 목록에서 가른다

모아봄이 지금 공식 문장만으로 일반 목록에 올릴 수 있는 실제 지원 정책은, 2026-11-04에 공식 페이지 본문을 연 **12건**이다. 10건 기준은 충족되고, 20건에는 아직 이르지 못했다. 가상 8건은 `local-grants.json`에 `sample: true`로 남아 있으며, 로컬 로더와 `GET /grants`, `GET /grants/{id}`, 추천 채점은 이 표시를 목록에서 빼지 않는다. `POST /policies/import`는 로컬 메모리에 새 행만 더하고 8건은 그대로 둔다. Django의 잡아바 스크립트와 빈 SQLite는 이 교체의 입력이 되지 못한다. 공공데이터포털에 올라온 온통청년·복지로·정부24 데이터셋은 비용이 무료라고 적혀 있으나, 키와 출력 필드와 호출 한도가 출처마다 다르고 이번 조사에서는 엔드포인트를 호출하지 않았다. 12건을 기존 매처에 넣으면 연령과 지역 일부만 구조화되고, 소득분위는 전부 비어 자격은 `CHECK_REQUIRED`가 된다. 추천 점수식, Java 인증, React 화면은 유지한 채, 이후 단계에서 사용자용 조회만 `sample: true`를 건너뛰면 예시는 테스트에 남고 일반 목록에서는 빠진다. 이번 단계는 애플리케이션 코드를 수정하지 않았고, 유료 API를 호출하지 않았으며, 배포하거나 커밋하지 않았다.

## 1. 현재 Java 모델과 로컬 로딩

`Grant`는 순서대로 `grantId`, `categoryTitle`, `title`, `description`, `endDate`, `link`, `eligibility`, `sample`, `keywords`, `sourceUrl`, `referenceDate`, `referenceText`, `applicationStart`, `sourceServiceId`의 15개 구성요소다. HTTP JSON은 `eligibility`를 중첩하고, DynamoDB와 `local-grants.json`은 자격 필드를 같은 높이의 평탄한 키로 둔다. 따라서 이후 실제 정책을 넣으려면 파일 모양을 응답 모양으로 오해하지 않고, 로더가 만드는 `Grant` 레코드에 맞춰야 한다 ([Grant.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/Grant.java), [local-grants.json](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/resources/local-grants.json)).

자격의 구성요소는 `targetAgeGroup`, `minAge`, `maxAge`, `minIncomeBracket`, `maxIncomeBracket`, `targetRegion`, `householdClarity`, `specialClarity`, `householdTypes`, `specialConditions`다. 명확도 열거형은 `UNRESTRICTED`, `SPECIFIED`, `UNKNOWN`이다. 명확도가 `SPECIFIED`가 아니면 대응 코드 목록은 빈 목록으로 저장된다. 가구 코드는 `SINGLE`, `NEWLYWED`, `MULTI_CHILD`, `SINGLE_PARENT`이고, 특수조건 코드는 `DISABLED`, `VETERAN`, `NEWLYWED`, `MULTI_CHILD`, `OTHER`이며, 모르는 코드는 예외가 된다. 나이, 지역, 소득의 빈 값은 제한 없음이 아니다. 가구·특수조건도 값이 없으면 `UNKNOWN`이고, 원문이 제한 없음이라고 밝힌 경우에만 `UNRESTRICTED`다 ([Eligibility.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/Eligibility.java), [PolicyCodes.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/PolicyCodes.java), [policy-data-mapping.md](file:///C:/Users/hyyyr/moabom/serverless/docs/policy-data-mapping.md)).

로컬 파일은 예시 8건의 JSON 배열이다. 여덟 행 모두 `sample`이 true이고, `householdClarity`와 `specialClarity`는 `UNRESTRICTED`이며, `referenceText`는 `테스트용 가상 데이터`다. 제목은 `[예시]`로 시작하고 링크는 `example.com`이다. `example-003-living-support`와 `example-007-senior`의 `endDate`는 null이다. 여덟 행 모두 `householdTypes`, `specialConditions`, `sourceUrl`, `referenceDate`, `applicationStart`, `sourceServiceId` 키가 없다. 이 8건이 제한 없음으로 읽히는 이유는 플래그가 아니라, 파일에 `UNRESTRICTED`가 적혀 있기 때문이다. `LocalCatalog`는 명확도 키가 없거나 잘못되면 `UNKNOWN`을 반환한다. 같은 매핑 문서의 앞문장(가구·특수 필드를 생략한 가상 행은 제한 없음으로 읽힌다)은 이 코드와 어긋나고, 같은 파일의 뒷문장(8건은 `UNRESTRICTED`를 명시했고 sample 플래그만으로 빈 값이 제한 없음이 되지 않는다)이 코드와 맞다 ([LocalCatalog.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/local/LocalCatalog.java), [policy-data-mapping.md](file:///C:/Users/hyyyr/moabom/serverless/docs/policy-data-mapping.md)).

`LocalCatalog.load()`는 클래스패스의 `local-grants.json`을 전부 `Grant`로 만들고 `sample: true`를 빼지 않는다. 파일이 없으면 `local-grants.json was not found on the classpath`로 실패한다. `sample`이 true인데 `referenceText`가 없으면 문구를 `테스트용 가상 데이터`로 채운다. `InMemoryGrantsRepository`는 파일을 열지 않고, 받은 목록을 `grantId` 순으로 정렬해 페이지를 낸다. 제거·교체 메서드는 없다. `listAllGrants`는 한 번에 100건씩 최대 20번, 상한 500건까지 읽으며 sample을 거르지 않는다. 로컬 서버 `LocalApiServer.start`가 `LocalCatalog.load()` 결과를 이 메모리 저장소에 넣고 목록·상세·임포트 핸들러에 넘긴다. 람다의 목록·상세는 `GRANTS_TABLE_NAME`이 필요한 DynamoDB를 읽고, `entityType = GRANT` 항목 중 `grantId`가 비어 있는 것만 버린다. DynamoDB에서 `sample` 속성이 없으면 false다. 배포 환경의 목록은 로컬 JSON을 읽지 않으며, 이 클래스들 안에 그 파일을 DynamoDB로 심는 기능은 없다 ([InMemoryGrantsRepository.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/InMemoryGrantsRepository.java), [DynamoGrantsRepository.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/DynamoGrantsRepository.java), [local-development.md](file:///C:/Users/hyyyr/moabom/serverless/docs/local-development.md)).

`serverless/seed/sample-grants.json`은 테스트 보조 `SampleGrants`가 가리키는 파일이고 런타임 카탈로그가 아니다. 그 파일과 `local-grants.json`의 행 단위 비교는 이번 조사에서 하지 않았다. `LocalCatalog`의 `item.get("sample").asBoolean()`은 null 검사가 없고, 현재 8건은 키가 모두 있어 그 경로는 실행되지 않는다.

## 2. GET /grants, GET /grants/{id}, POST /policies/import

`GET /grants`는 저장소 페이지를 그대로 반환한다. 기본 limit은 20, 최대는 100이다. 범위를 벗어나거나 정수가 아니면 400과 `limit은 1 이상 100 이하의 정수여야 합니다.`다. `nextToken`은 `^[A-Za-z0-9][A-Za-z0-9-]{0,79}$`가 아니면 400이다. 성공 본문은 `{ "grants": ... }`이고, 다음 토큰이 있을 때만 `nextToken`을 붙인다. `sample: true` 행이 포함된다. Authorization 헤더를 읽지 않는다. `GET /grants/{id}`의 본문은 `{ "grant": ... }`가 아니라 `Grant` 객체 자체다. 식별자 형식이 같아야 하고, 없으면 404 `지원금을 찾을 수 없습니다.` 이 응답은 `localDev`가 false라 `X-Moabom-Local-Dev`를 붙이지 않는다. 직렬화 키에는 `sample`, 키워드, 출처 필드, 가구·특수 명확도와 코드 목록이 들어간다. 핸들러 테스트도 가상 카탈로그 본문에 `"sample": true`가 있기를 기대한다 ([ListGrantsHandler.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/ListGrantsHandler.java), [GetGrantHandler.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/GetGrantHandler.java)).

SAM은 스테이지 `dev`의 `MoabomGrantsApi`에 `GET /grants`와 `GET /grants/{id}`만 연결한다. 두 함수는 DynamoDB Query·GetItem과 `GRANTS_TABLE_NAME`을 갖고, 이벤트에 `Auth`가 없다. `template.yaml`에서 Authorizer는 찾지 못했다. CORS가 `Authorization` 헤더를 허용하는 것은 토큰을 요구하는 설정이 아니다. 로컬 디스패치도 이 두 경로에서 인증 핸들러를 먼저 호출하지 않는다. 이 두 조회의 인증이 없는 상태는 코드와 템플릿에 이미 있으므로, 인증을 바꾸지 않는다는 조건은 여기에 인증을 새로 넣지 않는다는 뜻이다. 배포된 스테이지를 실제로 조회하지는 않았고, 로컬 개발 문서도 이 작업 공간에서 스택을 배포하지 않았다고 적는다 ([template.yaml](file:///C:/Users/hyyyr/moabom/serverless/template.yaml)).

`POST /policies/import`는 소스 주석과 템플릿이 모두 로컬 전용이라고 보는 경로다. `template.yaml`에 임포트 함수, `/policies` 경로, 해당 메서드가 없다. CORS의 `POST` 허용은 이 메서드를 만들지 않는다. `LocalApiServer`만 `127.0.0.1`에서 이 경로를 받는다. 본문은 `format`이 `json` 또는 `csv`인 객체다. JSON은 `records` 배열, CSV는 `content` 문자열이 필요하다. 필수 값은 `serviceId`와 `serviceName`이다. `sample`이 없거나 공백이면 false로 저장되어 공개 정책 행이 된다. `true`/`false`가 아니면 `sample은 true 또는 false여야 합니다. 테스트 데이터로 추정하지 않습니다`로 그 행이 거절된다. 날짜 `referenceDate`, `applicationStart`, `applicationEnd`는 `yyyy-MM-dd`만 허용되고, 다른 형식은 고쳐서 넣지 않고 행 오류가 된다. 나이는 0 이상 120 이하, 소득분위는 1 이상 10 이하의 정수이며 역전된 범위는 추정하지 않고 거절된다. 가구·특수 코드는 `|` 또는 `,`로 나누며 `PolicyCodes`에 있어야 한다. 명확도 문자열이 인식되지 않으면 경고만 하고 제한 없음으로 보지 않는다. `SPECIFIED`인데 코드가 비어 있으면 제한 없음으로 바꾸지 않고 `UNKNOWN`으로 저장한다. `UNRESTRICTED`는 그 문자열이 들어온 경우에만 유지된다 ([PolicyImportHandler.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/PolicyImportHandler.java), [PolicyImporter.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/PolicyImporter.java), [PublicPolicyMapper.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/PublicPolicyMapper.java)).

매퍼는 `categoryTitle`을 항상 `미분류`, `keywords`를 항상 빈 목록, `targetAgeGroup`을 항상 null로 둔다. 설명은 `summary`, 종료일은 `applicationEnd`, 링크는 `applicationLink`가 있으면 그것을 쓰고 없으면 `serviceUrl`이다. `sourceUrl`은 `serviceUrl`이다. `sourceServiceId`는 출처 이름과 서비스 ID를 콜론으로 잇고, 출처 이름이 비면 `public-policy`가 된다. `grantId`는 `policy-` 뒤에 서비스 ID를 소문자로 바꾸고 `[a-z0-9-]`가 아닌 문자를 하이픈으로 접어 80자까지 자른 값이다. 같은 `sourceServiceId`, 같은 정규화 `sourceUrl`, 또는 제목·지역·시작일·종료일이 모두 비어 있지 않고 같으면 중복으로 보고 기존 행을 유지한다. 제목 비교에서는 앞의 `[예시]`를 뺀다. 빈 토큰끼리는 같은 정책으로 보지 않는다. 예시 8건은 `sourceServiceId`, `sourceUrl`, `applicationStart`가 null이고 식별자가 `example-`로 시작하는 반면 임포트 식별자는 `policy-`로 시작하므로, 실제 행을 더해도 이 중복 규칙으로 8건이 빠지지 않는다. 임포트는 행을 삭제하지 않으며 DynamoDB에도 쓰지 않는다. 응답의 `sampleCount`는 추가 뒤 `sample`이 true인 개수고, `localDevOnly`는 true다. 아무것도 안 들어왔고 오류가 중복 이외의 것이면 400, 중복만 있으면 200이다. 테스트는 임포트 뒤에도 sample 8건과 `sampleCount` 8을 기대한다 ([GrantNormalizer.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/GrantNormalizer.java), [PolicyClarityAndImportTest.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/test/java/com/moabom/grants/PolicyClarityAndImportTest.java)).

홈 화면은 `getGrants()`가 쿼리와 토큰 없이 받은 `grants` 배열을 그대로 그린다. `sample` 필터는 없고, true면 라벨 `예시`, false면 `공개자료`다. 검색어 `q`만 제목과 설명을 거른다. `nextToken`을 따라가지 않으므로 화면에는 핸들러 기본 20건까지 나온다. 빈 목록 문구 `표시할 예시 지원금이 없습니다.`는 고정 문장이지 필터가 아니다. 추천 카드도 sample 행을 빼지 않는다. 상세와 스크랩은 확인한 범위에서 `sample`을 라벨(`테스트용 가상 데이터` 대 `공개 정책 데이터`, `예시` 대 `공개자료`)에만 쓴다. 따라서 예시를 일반 화면에서 없애려면 React 디자인을 바꿀 필요 없이, 그 화면이 읽는 응답에 예시 행이 없으면 된다. 섹션 제목은 `실시간 인기 지원금 살펴보기`이지만 읽는 값은 카탈로그 순서다 ([HomePage.jsx](file:///C:/Users/hyyyr/moabom/frontend/src/pages/HomePage.jsx), [moabomApi.js](file:///C:/Users/hyyyr/moabom/frontend/src/api/moabomApi.js)).

## 3. Django 수집 코드 재사용 여부

재사용하지 않는다. 남겨 두어도 Java 런타임은 바뀌지 않는다. `backend`를 2026-11-04에 읽기만 했을 때, 수집 코드는 `crawlers/jobaba_crawler.py`와 `crawlers/cheongnyeontest.py` 두 스크립트뿐이었다. 둘 다 `https://apply.jobaba.net/special/gibon/bsnsInfo.do` 한 페이지를 향하고, 관리 명령·Scrapy 스파이더·복지로 클라이언트·data.go.kr 클라이언트·Django 저장이 없다. `crawlers`는 `INSTALLED_APPS`에 없고 URL에도 없다. Java 트리에는 `crawlers`, `db.sqlite3`, `test_data.json` 참조가 없다. 현재 인터프리터 Python 3.14.7에서는 `django`, `bs4`, `scrapy`가 임포트되지 않고 `requests`만 된다. 컴파일된 파일은 `cpython-311`이고 마이그레이션 헤더는 Django 5.2.6이다. `requirements.txt`와 가상환경은 `backend` 안에 없다 ([jobaba_crawler.py](file:///C:/Users/hyyyr/moabom/backend/crawlers/jobaba_crawler.py), [PYTE/settings.py](file:///C:/Users/hyyyr/moabom/backend/PYTE/settings.py)).

스크립트 딕셔너리 키는 `grant_title`, `grant_description`, `application_deadline`, `application_link`, `target_age_group`, `min_age`, `max_age`, `min_income_bracket`, `max_income_bracket`, `target_region`이다. 페이지 URL, 원문 HTML, 서비스 ID, 출처 이름은 넣지 않는다. 나이는 19와 34, 지역은 `Gyeonggi-do`, 연령 그룹은 `Youth`로 코드에 고정되어 있고, 주석은 이것을 페이지에서 뽑아야 할 임시 기본값이라고 적는다. 소득분위는 None이다. ## 5. 추천 알고리즘 필드 매핑

점수식은 `score = 0.6 * contentSimilarity + 0.4 * behaviorInterest`이고 `behaviorInterest = 0.5 * directAction + 0.5 * categoryAffinity`다. 발표 값은 소수 넷째 자리 반올림, 상위 5건, 동점이면 `ELIGIBLE` 다음 `CHECK_REQUIRED`, 그다음 `grantId` 오름차순이다. 이 식은 유지한다. 내용 유사도는 사용자 토큰과 지원금 토큰의 코사인이다. 지원금에서 읽는 토큰은 `c:`와 `categoryTitle`, `k:`와 `keywords`다. 관심이나 지원금 토큰이 비면 0이다. `directAction`은 그 `grantId`의 이력에 `SCRAP`이 있으면 1, `VIEW`만 있으면 0.5, 아니면 0이다. 채점기는 `sample`, 제목, 설명, 날짜, 링크, 출처 필드, `targetAgeGroup`을 읽지 않고 sample로 행을 빼지도 않는다. `RecommendHandler`는 `listAllGrants()`를 채점하므로 지금 구조에서는 예시 행도 같은 식으로 점수가 매겨진다 ([RecommendationScorer.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/RecommendationScorer.java), [ScoringPolicy.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/ScoringPolicy.java), [recommendation-algorithm.md](file:///C:/Users/hyyyr/moabom/serverless/docs/recommendation-algorithm.md)).

채점 전에 `EligibilityEvaluator`가 나이, 지역, 소득, 가구, 특수의 다섯 검사를 한다. 하나라도 `FAIL`이면 `INELIGIBLE`이고 채점에서 빠진다. `FAIL` 없이 `UNKNOWN`이 있으면 `CHECK_REQUIRED`로 남고 점수는 계산된다. 전부 `PASS`면 `ELIGIBLE`이다. 나이는 `minAge`, `maxAge`, 사용자 나이를 본다. 두 경계가 모두 null이거나 사용자 나이가 없거나 경계가 하나만 있으면 `UNKNOWN`이다. 두 경계가 있고 그 폐구간 안이면 `PASS`, 밖이면 `FAIL`이다. `targetAgeGroup`은 보지 않는다. 지역은 앞뒤 공백을 제거한 뒤 비교한다. 정책 지역이 null이면 `UNKNOWN`이고, `전국`으로 시작하면 사용자 지역이 비어 있어도 `PASS`다. 그 외에는 문자열이 같으면 `PASS`, 다르면 `FAIL`이다. 부분 문자열이나 광역-기초 포함 관계는 없다. 소득분위도 나이와 같은 양끝·단일 경계 규칙이고 값은 1 이상 10 이하다. 가구와 특수는 `UNRESTRICTED`면 `PASS`, null이나 `UNKNOWN`이면 `UNKNOWN`, `SPECIFIED`인데 사용자 목록이 비면 `UNKNOWN`, 코드가 겹치면 `PASS`, 사용자 목록이 있는데 안 겹치면 `FAIL`이다. 알고리즘 문서 앞부분의 세 검사(나이·지역·소득) 설명과, 로컬 개발 문서의 「논문에 쓸 수 있는 설명」에 있는 가구·특수조건 향후 과제 문장은 다섯 검사를 하는 현재 코드보다 오래된 문장이다 ([EligibilityEvaluator.java](file:///C:/Users/hyyyr/moabom/serverless/grants-api/src/main/java/com/moabom/grants/EligibilityEvaluator.java)).

임포트만 거치면 분류가 `미분류`이고 키워드가 빈 목록이라, 사용자 관심에 `미분류`가 없으면 내용 유사도 기여는 0이다. 키워드 토큰은 생기지 않는다. 이것은 점수식의 문제가 아니라 임포트가 분류와 키워드를 입력으로 받지 않기 때문이다. 아래 12건의 공식 페이지 기록에는 채점기가 읽는 분류 토큰과 키워드 목록이 없다. 그 페이지 문장으로 키워드를 만들지 않는다. 행동 이력은 `grantId` 기준으로 남으므로, 내용 토큰이 없어도 조회·스크랩이 있으면 0.4 쪽 항은 지금의 식 그대로 움직인다.

## 7. 구현 순서와 해야 할 일, 이번 단계에서 하지 않은 일

교체는 파일에서 8건을 지우는 작업이 아니다. 테스트는 `LocalCatalog.load()`가 sample인 8건을 돌려주기를 기대하고, 임포트는 그 8건을 지우지 못한다. 일반 화면은 API가 준 배열을 그대로 그린다. 그래서 예시는 테스트 파일에 두고, 사용자용 읽기 경로만 `sample: true`를 건너뛴 다음, 확인된 12건을 `sample: false`로 옆에 둔다. 점수식의 0.6과 0.4, `GET /grants`와 `GET /grants/{id}`의 무인증, React 라벨과 배치는 이 순서에서 바꾸지 않는다.

첫째, 입력 재료를 위 12건 표와 매퍼 표로 고정한다. Django 스크립트, `test_data.json`, 빈 SQLite, 15083323 CSV, 호출하지 않은 API 응답은 행을 만드는 데 쓰지 않는다. 각 행의 `serviceId`는 URL 경로에 이미 있는 토큰만 쓰고, `sample`은 false, 공식 URL은 `sourceUrl`과 링크에 둔다. 나이·지역·가구는 5절 표에 있는 것만 채운다. 소득분위, 특수조건, 신청 시작·종료일은 비워 임포트와 평가기가 `UNKNOWN`으로 보게 한다. `UNRESTRICTED`와 `전국`은 쓰지 않는다. 기간의 한글 문장은 `referenceText`에만 둔다. 분류와 키워드는 페이지 기록에 없으므로 만들지 않는다. 임포트 경로를 쓰면 분류는 `미분류`, 키워드는 빈 목록이 되고, 사용자 관심에 그 분류가 없으면 내용 유사도는 0인 채로 행동 이력 항만 남는다. 이것은 식의 변경 없이 받아들이는 데이터 모양이다.

둘째, `local-grants.json`의 예시 8건은 테스트 고정으로 유지한다. 그 파일에 12건을 섞으면 `LocalCatalog.load()`의 8건 기대와 어긋난다. 실제 12건은 두 번째 JSON으로 두고, 이후 로컬 서버가 예시 파일과 실제 파일을 함께 읽게 한다. `POST /policies/import`로 메모리에만 더하면 프로세스가 끝나는 순간 사라지고, 예시를 지우지 않으며, DynamoDB에도 닿지 않는다. 배포된 `GET /grants`는 DynamoDB를 읽으므로 로컬 파일을 바꾸는 것만으로는 배포 목록이 바뀌지 않는다. DynamoDB 시드는 현재 클래스에 없다. 이 순서에서는 시드를 만들지 않고, `/policies/import`를 API Gateway에 올리지 않으며, Authorizer를 추가하지 않는다.

셋째, 사용자용 목록·상세·추천이 읽는 경로에서 `sample: true`를 제외한다. 목록과 상세는 홈, 상세, 추천이 받는 페이로드에서 예시가 빠지게 하고, 없는 예시를 상세에서 물어보면 지금의 404 문구를 그대로 쓴다. 추천은 채점 전에 예시 행만 건너뛴다. 가중치, 동점 순서, 다섯 자격 검사는 그대로다. 테스트는 `LocalCatalog.load()`와 저장소를 직접 읽어 8건을 계속 본다. 공개 목록 본문에 `"sample": true`가 있기를 기대하는 핸들러 테스트만, 필터를 넣는 그 변경에서 기대값을 고친다. 홈은 받은 `grants`를 그리고 `sample: false`를 이미 `공개자료`로 표시하므로 화면 구성은 바꾸지 않는다. 기본 20건 안에 예시 8건과 실제 12건이 함께 있으면 한 페이지에 모두 들어가고, 정렬이 `grantId`순이라 `example-`이 `policy-`보다 앞에 온다. 필터 이후 홈에는 12건이 남는다. 스크랩 화면은 라벨 분기 너머를 끝까지 따라가지 못했으므로, 이미 저장된 예시 식별자가 스크랩 저장소에 남아 있는지는 그 저장소를 읽는 후속 확인이 필요하다.

넷째, 키 대량 수집은 12건을 로컬에 올린 뒤로 미룬다. 그 시점의 선행 확인은 온통청년 출력 표 또는 시간 초과였던 정책 API 문서, 15090532 활용가이드와 SWAGGER, 15108347 코드표, 15113968 인증 파라미터 이름이다. 색인에만 있던 개발계정 100회, 1,000회, 10,000회는 같은 페이지를 다시 열어 블록이 보이는지 확인한 뒤에 호출 계획에 쓴다. 운영계정 일일 횟수는 확인되기 전에는 숫자로 잡지 않는다. 15083323은 이름과 URL의 대조 목록으로만 쓸 수 있고, 그 CSV의 빈 대상·소득·지역을 제한 없음으로 해석하지 않는다.

이번 단계에서 하지 않은 일은 분명하다. 애플리케이션 코드를 수정하지 않았다. 유료 API를 호출하지 않았고, 무료로 적힌 오픈API 엔드포인트도 호출하지 않았으며 키를 발급하지 않았다. CSV를 다운로드하지 않았다. 배포하지 않았고 커밋하지 않았다. Django 크롤러를 실행하지 않았고 패키지를 설치하지 않았다. 추천 점수식, Java 인증, React 화면은 손대지 않았다.

## 결론

막힌 지점은 공식 사이트의 부재가 아니다. 확인된 12건의 문장은 중위소득 비율, 학자금 구간, 한글 신청 기간으로 적혀 있고, 모아봄 매처는 소득분위 1–10, `yyyy-MM-dd`, 지역 문자열의 완전 일치만 자격의 `PASS`로 받는다. 그 간격을 환산으로 메우면 페이지에 없는 조건이 생긴다. 빈 칸을 `UNKNOWN`으로 두면 12건은 추천에 `CHECK_REQUIRED`로 남고, 그것이 현재 식과 다섯 검사가 정한 정상 상태다. 가상 8건을 일반 화면에서 빼는 일도 삭제가 아니라 읽기 경로의 분리이고, 테스트와 로컬 임포트가 이미 그 8건의 존속을 전제한다. 키와 비어 있는 필드표가 채워지기 전에는, 손입력한 이 12건이 공식 출처로 검증된 카탈로그의 전부다.
