# 모아봄 추천 점수

이 점수는 초기 식입니다. 사용자 실험이나 클릭 데이터로 맞춘 가중치가 아닙니다.

```text
score = 0.6 × contentSimilarity + 0.4 × behaviorInterest
```

세 값 모두 0 이상 1 이하입니다. 응답에 넣는 수는 반올림하여 소수 넷째 자리까지 표시합니다.

## 자격 검증

연령, 지역, 소득분위를 각각 비교합니다.

- 사용자 값과 정책 조건이 모두 있고 범위를 벗어나면 `FAIL`입니다. 연령과 소득분위는 양 끝 값을 포함합니다.
- 지역은 공백을 제거한 뒤 문자열이 같을 때만 통과합니다. 대상 지역이 `전국`으로 시작하면 지역 제한이 없는 것으로 봅니다.
- 사용자 값이나 정책의 상한·하한이 없으면 통과로 간주하지 않고 `UNKNOWN`입니다.
- 하나라도 `FAIL`이면 `INELIGIBLE`이며 추천 목록에서 제외합니다.
- `FAIL`은 없고 `UNKNOWN`이 있으면 `CHECK_REQUIRED`로 추천에 남깁니다.
- 세 항목이 모두 `PASS`이면 `ELIGIBLE`입니다.

## 관심 분야

행동 이력이 가리키는 지원금의 카테고리와 키워드에 가중치를 더합니다.

- 조회 `VIEW`는 1입니다.
- 스크랩 `SCRAP`는 2입니다.
- 목록에 없는 지원금의 행동은 관심 계산에서 빠집니다.
- 같은 지원금을 여러 번 조회하거나 스크랩하면 가중치를 누적합니다.

## 콘텐츠 유사도

사용자 관심 가중치 벡터와 지원금 토큰 벡터의 코사인 유사도입니다.

- 카테고리 토큰은 `c:카테고리`, 키워드 토큰은 `k:키워드`입니다.
- 지원금 토큰의 값은 1이고, 같은 키워드는 한 번만 계산합니다.
- 관심 이력이 없거나 지원금에 토큰이 없으면 0입니다.

## 행동 관심도

```text
behaviorInterest = 0.5 × directAction + 0.5 × categoryAffinity
```

- `directAction`은 그 지원금을 스크랩했으면 1, 조회만 했으면 0.5, 아니면 0입니다.
- `categoryAffinity`는 그 카테고리에 쌓인 가중치를 사용자 카테고리 가중치의 최댓값으로 나눈 값입니다.
- 최댓값이 0이면 카테고리 관심도도 0입니다.

## 정렬

1. 점수가 높은 순
2. 점수가 같으면 `ELIGIBLE`을 `CHECK_REQUIRED`보다 앞
3. 그래도 같으면 `grantId`의 오름차순

이 순서는 무작위 요소가 없어 같은 입력이면 같은 순위가 됩니다. 행동 이력이 없는 사용자는 유사도와 관심도가 0이므로, 자격 검증에서 제외되지 않은 지원금을 위 정렬로 최대 5건 추천합니다.

## 데이터 접근

지원금 테이블의 키는 바꾸지 않습니다. 파티션 키는 `entityType`, 정렬 키는 `grantId`입니다.

- 목록은 `entityType = GRANT` Query입니다.
- 상세는 같은 키로 GetItem입니다.
- 추천은 지원금 파티션을 Query로 페이지 조회한 뒤 함수 안에서 점수를 계산합니다. 최대 500건입니다.

사용자 프로필과 행동은 지원금 정렬 키 이름이 `grantId`라서 같은 테이블에 넣지 않습니다.

- 프로필 테이블 키는 `userId`이고 조회는 GetItem입니다.
- 행동 테이블 키는 `userId`와 `behaviorSk`입니다. 같은 사용자의 같은 행동 유형과 지원금은 `behaviorSk`를 `유형#지원금ID`로 고정해 한 건만 저장합니다. 발생 시각은 속성으로 보관하며, 이미 있으면 다시 쓰지 않습니다.
- 한 사용자의 이력은 `userId` Query입니다.

사용자별 API는 템플릿 매개변수 `EnableUnauthenticatedUserRoutes`가 `true`일 때만 만들어집니다. 기본값은 `false`입니다. 인증이 없으므로 공개 배포에 켜면 안 됩니다.

## 배포 전 확인

Lambda 문서에는 Java 25 런타임 식별자 `java25`가 있습니다. 이 개발 환경에는 AWS SAM CLI가 없어 `sam validate`는 실행하지 않았습니다. 배포 전에 사용할 SAM CLI 버전과 대상 리전에서 `java25`를 다시 확인해야 합니다.

## 스크랩 취소

`DELETE /users/{id}/events`는 본문의 유형이 `SCRAP`일 때만 `behaviorSk`가 `SCRAP#지원금ID`인 행을 삭제합니다. 조회 행은 남깁니다. 행이 없으면 오류가 아니라 `deleted: false`와 상태 200을 돌려주고, 다음 추천은 남은 이력만 사용합니다.

## 가구 형태와 특수조건

연령, 지역, 소득분위 규칙은 그대로입니다. 가구 형태와 특수조건은 같은 판정 순서에 추가됩니다.

- 정책이 제한 없음이면 통과입니다.
- 정책 조건이 확인되지 않으면 추정하지 않고 UNKNOWN입니다.
- 정책이 대상 코드를 지정했는데 사용자 선택이 없으면 UNKNOWN입니다.
- 사용자 선택과 정책 대상이 하나라도 겹치면 통과이고, 선택이 있는데 겹치지 않으면 FAIL입니다.
- FAIL이 하나라도 있으면 추천에서 제외합니다. FAIL 없이 UNKNOWN이 있으면 CHECK_REQUIRED입니다.

점수식은 바꾸지 않았습니다.
저장된 가구 형태·특수조건 값이 없으면 예시 지원금이라도 `UNKNOWN`입니다. `UNRESTRICTED`는 원문에 제한 없음이 적힌 경우만 통과입니다. 점수식은 바꾸지 않았습니다.
